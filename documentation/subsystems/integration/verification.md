## INT-9 inspection checklist

Inspect the code on the branch under review. Record the reviewer, the date and the commit.

- [ ] No model in `src/bugs26/integration/models.py` has a field for a reporter, author, user, login, email, IP address or session. Check every class in the file: `RawReport`, `StructuredReport`, the `IE...` classes, `CIRequest`, the `CI...` classes and `MaintainerOutput`.
- [ ] `src/bugs26/integration/github.py` returns only title, body, URLs, issue number, label names and timestamps, and only for repositories in `supported_repos.txt`. The GitHub `user` object, and every other field in the API answer, is dropped.
- [ ] No identifier is shared between two submissions. `report_id`, `request_id` and `snapshot_id` are new random UUIDs for each submission. `RawReport.sha256` is a content hash of the report (title and body); it is not sent to IE or CI, not a reporter identity. Two identical reports give the same hash, which says nothing about who sent them.
- [ ] No code writes to disk or to a database. Search `src/` for `open(`, `sqlite`, `pickle`, `shelve` and file writes.
- [ ] No code logs. Search `src/` for `logging`, `print` and `logger`.
- [ ] No cache or global holds reports between requests.
- [ ] `src/bugs26/web/__main__.py` starts uvicorn with `access_log=False`. Start the server with `python -m bugs26.web`, send a request, and check that no request line is printed.
- [ ] The JSON download on the result page is a `data:` link. The server keeps nothing.
- [ ] The placeholder IE and CI stubs add no identity fields. Real IE and CI code must be inspected the same way when it replaces them.
